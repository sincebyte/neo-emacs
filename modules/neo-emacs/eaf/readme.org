* EAF Browser

EAF (Emacs Application Framework) is a framework that extends Emacs with modern graphical capabilities by embedding a Qt6 WebEngine view. EAF Browser is the web browser application built on it — a full-featured, keyboard-driven browser that runs inside Emacs.

* Install

** System Dependencies (macOS)

EAF depends on Qt6 WebEngine and Python. Install them via brew:

#+begin_src shell
brew install python@3.13 qt6 pyqt6
#+end_src

Use Python 3.13 (the recommended version). Make sure =python3= points to the brew-installed one:

#+begin_src shell
which python3
# should output /opt/homebrew/bin/python3
#+end_src

** Install aria2 (optional, for downloads)

#+begin_src shell
brew install aria2
#+end_src

** Install pycookiecheat (optional, for Chrome cookie import)

#+begin_src shell
pip3 install pycookiecheat
#+end_src

** Install EAF Framework + Browser

Neo-emacs uses doom's =straight.el= to install both =eaf= and =eaf-browser= from source. The package recipes are in =packages.el=:

#+begin_src elisp
(package! eaf
  :recipe (:host github
           :repo "emacs-eaf/emacs-application-framework"
           :branch "master"
           :files ("*.el" "*.json" "*.py" "core" "app")))

(package! eaf-browser
  :recipe (:host github
           :repo "emacs-eaf/eaf-browser"
           :branch "master"
           :files (:defaults "*.py" "dependencies.json" "easylist.txt" "aria2-ng" "node_modules")))
#+end_src

After the packages are pulled, run the EAF installer to set up Python dependencies:

#+begin_src shell
cd ~/.emacs.d/.local/straight/repos/emacs-application-framework/
python3 install-eaf.py
#+end_src

Or use =M-x eaf-install-and-update= inside Emacs.

** Verify Installation

Open EAF's demo to check everything works:

#+begin_src elisp
M-x eaf-open-demo
#+end_src

If the demo window appears, EAF is installed correctly.

* Configuration

Neo-emacs configures EAF Browser in =config.el= with sensible defaults:

** Core Settings

#+begin_src elisp
(setq eaf-python-command "/opt/homebrew/bin/python3"
      eaf-browser-continue-where-left-off t
      eaf-browser-enable-adblocker t
      eaf-proxy-type "http"
      eaf-proxy-host "127.0.0.1"
      eaf-proxy-port "10887"
      eaf-start-python-process-when-require nil)
#+end_src

** Proxy & Chromium Flags

QtWebEngine runs Chromium under the hood. Neo-emacs configures proxy and flags via environment variables:

#+begin_src elisp
(setenv "QTWEBENGINE_CHROMIUM_FLAGS"
        "--no-sandbox --disable-features=WebRtcHideLocalIpsWithMdns
         --enable-features=PlatformHEVCDecoderSupport
         --enable-gpu-rasterization --ignore-gpu-blocklist
         --proxy-server=http://127.0.0.1:10887
         --user-agent=\"Mozilla/5.0 ...\"")
(setenv "QTWEBENGINE_DISABLE_SANDBOX" "1")
#+end_src

Proxy auto-toggle is handled by an advice:

#+begin_src elisp
(defun my/eaf-enable-proxy (&rest _)
  (ignore-errors
    (when (and (boundp 'eaf-proxy-type) eaf-proxy-type eaf-epc-process)
      (eaf-call-async "toggle_proxy"))))
(advice-add 'eaf-open-browser :after #'my/eaf-enable-proxy)
#+end_src

** EAF Browser Mode Key Bindings

EAF Browser defaults to =input mode= on startup — all keys are sent directly to the web page. Press =M-i= or =s-i= to toggle back to =insert mode= for EAF commands.

*** Auto-Input Mode

When EAF browser opens, neo-emacs automatically enters input mode after a 0.5s delay:

#+begin_src elisp
(defun my/eaf-auto-input-mode (&rest _)
  (ignore-errors
    (when (and (boundp 'eaf-epc-process) eaf-epc-process)
      (let ((buffer-id eaf--buffer-id))
        (run-at-time 0.5 nil
                     (lambda ()
                       (eaf-call-async "eval_function" buffer-id "switch_to_input_mode" "t")))))))
(advice-add 'eaf-open-browser :after #'my/eaf-auto-input-mode)
#+end_src

The event string ="t"= makes =switch_to_input_mode= enable input mode idempotently, so a later =s-i= press always re-enables it instead of toggling it off.

*** Input Mode Toggle

| Key    | Command                  | Description                                          |
|--------+--------------------------+------------------------------------------------------|
| M-i, s-i | my/eaf-toggle-input-mode | Enable input mode (idempotent) + hand focus to browser |

Both =M-i= and =s-i= run =my/eaf-toggle-input-mode=, which sends the event string ="t"= to =switch_to_input_mode=, enabling input mode without toggling it back off — so a single press always transfers keyboard focus to the Qt browser. On macOS the newer EAF activates the EAF (Qt) application when enabling and re-activates Emacs when disabling (or when Emacs regains focus). Left-clicking inside the browser also enables input mode and gives it focus.

The Python side reports every input-mode change back to Emacs via =eaf--toggle-input-mode=; an =:after= advice (=my/eaf-on-input-mode-enabled=) re-runs =my/eaf-toggle-input-mode= for that report, so a mouse click triggers the same idempotent enable path as the keybinding. The state is tracked in the buffer-local =my/eaf-input-mode=, and the whole chain is guarded against recursion.

** Chrome Cookie Import

When =eaf-browser-auto-import-chrome-cookies= is set to =t=, EAF Browser automatically imports cookies from Chrome on startup. You don't need to log in separately.

Supported Chrome-based browsers: =Chrome= (default), =Chromium=, =Brave=. Set via =eaf-browser-chrome-browser-name=.

* Vendored Python Patches (persist across updates)

Some fixes touch EAF's Python core (Qt/PyQt) and cannot be expressed in Emacs Lisp. They are kept as vendored files under =~/.doom.d/patches/eaf/core/= and are automatically copied back into the straight-managed source on every Emacs startup by =my/eaf-apply-patches= (defined at the top of =config.el=).

- =core/webengine.py=
  - =switch_to_input_mode= honors an event string: ="t"= enables input mode idempotently, ="nil"= disables, otherwise it toggles. Enabling also activates the EAF (Qt) application and retries giving keyboard focus to the browser view window, so a single =M-i=/=s-i= press (or click) reliably transfers focus.
  - Left-clicking inside the browser (when not in input mode) enables input mode, so a mouse click also hands focus to the browser.
  - Mouse release no longer returns focus to Emacs while in input mode.
- =core/macos.py=
  - Resets =input_mode= to =nil= whenever Emacs regains focus, so a later =M-i=/=s-i= press starts from a known OFF state instead of accidentally disabling an already-enabled mode.
- =core/buffer.py=
  - Keeps the scene rectangle in sync with the view size on resize (=setSceneRect=).

Why it exists: =doom sync= / package updates reset the straight repo and would silently discard these edits. =my/eaf-apply-patches= compares each vendored file with the repo copy (byte-for-byte) and copies it over only when they differ, so the fixes survive updates. If an update resets the repo, simply restart Emacs to re-apply.

#+begin_src elisp
(defun my/eaf-apply-patches (&optional force)
  "Apply EAF Python patches from ~/.doom.d/patches/eaf/ to the straight repo."
  (let* ((repo (expand-file-name
                "straight/repos/emacs-application-framework/"
                (or (bound-and-true-p doom-local-dir)
                    "~/.config/emacs/.local/")))
         (patch-dir (expand-file-name
                     "patches/eaf/"
                     (or (bound-and-true-p doom-user-dir) "~/.doom.d/"))))
    (dolist (rel '("core/webengine.py" "core/macos.py" "core/buffer.py"))
      (let ((target (expand-file-name rel repo))
            (source (expand-file-name rel patch-dir)))
        (when (and (file-exists-p source)
                   (or force
                       (not (my/eaf--files-same-contents-p source target))))
          (copy-file source target t)
          (message "[EAF] applied patch: %s" rel))))))
(my/eaf-apply-patches)
#+end_src

Note: the vendored files overwrite any upstream changes in those three files (a small fork). If upstream EAF significantly changes them, update the copies under =~/.doom.d/patches/eaf/core/= accordingly.

Also see the fringe fix in =config.el=: EAF buffers get zero-width fringes so the focus-lost screenshot is aligned with the widget position (fixes a 5–15px rightward content shift).

* Troubleshooting

** EAF doesn't start

- Check =eaf-python-command= points to the correct Python 3.13
- Run =M-x eaf-install-and-update= to install missing Python deps
- Check the =*eaf*= buffer for error messages

** Sandbox issues on macOS

EAF disables sandboxing by default (=QTWEBENGINE_DISABLE_SANDBOX=1=) because QtWebEngine sandboxing conflicts with some macOS configurations.

** Proxy not working

Ensure your proxy settings are correct in =config.el=. The proxy is toggled automatically when opening a browser, but verify with =eaf-proxy-type=, =eaf-proxy-host=, and =eaf-proxy-port=.

** Update EAF

#+begin_src shell
cd ~/.emacs.d/.local/straight/repos/emacs-application-framework/
git pull
python3 install-eaf.py
#+end_src

Then run =doom sync= in Emacs to rebuild.

After an update resets the repo, the vendored patches under =~/.doom.d/patches/eaf/core/= are re-applied automatically on the next Emacs startup (see "Vendored Python Patches"). Restart the EAF process (=M-x eaf-restart-process=) to load the patched Python code.
