#+TITLE: Emacs Typing Agent

#+STARTUP: overview indent
#+PROPERTY: header-args:elisp :results silent
#+PROPERTY: header-args:bash :results silent

让 OpenCode 生成结构化编辑任务，由 Emacs + Evil 用*可见的真实按键*逐字符修改代码，
并在结束前校验、保存、支持撤销。Emacs 是唯一的执行者；OpenCode 从不直接写目标文件。

* 它是什么

这个模块解决一个问题：演示/录制“AI 在编辑器里写代码”时，不能作弊地一次性插入整段文本。
Typing Agent 把修改拆成一个个操作（定位、进入 Insert、逐字符输入、删除、保存……），
慢速调度到 Emacs 的输入事件上，屏幕上看到的就是真实敲键盘的结果。

几个关键保证：

- *状态正确*：每个操作都检查 Evil 状态，Insert/Normal 不对就报错，绝不在未知状态乱发按键。
- *逐字符*：`type_text` / `replace_region` 是定时器驱动的一次一个字符，不是插入后再伪装。
- *内容可信*：输入完成后逐个字符比对 buffer；保存前按 `expected` 校验，保存后回读磁盘比对。
- *可回滚*：任务开始时保存快照，`undo` 回到快照并把结果写回文件。
- *不改你的配置*：任务期间只做动态绑定，临时关闭自动缩进/配对等干扰，结束即恢复。
  唯一例外是让该 buffer 的语法诊断改走回显区，避免 `popup.el` 往文件末尾插空行。

* 安装

** 作为 Doom 私有模块

模块已经放在 =~/.doom.d/modules/neo-emacs/typing-agent/=，并在 =init.el= 的
=:neo-emacs= 下启用：

#+begin_src elisp
(neo-emacs +typing-agent)
#+end_src

然后同步并重启：

#+begin_src bash
doom sync
#+end_src

** 安装 OpenCode 集成

#+begin_src bash
mkdir -p ~/.config/opencode/tools ~/.config/opencode/skills
cp ~/.doom.d/modules/neo-emacs/typing-agent/opencode/tools/typing-agent.ts \
   ~/.config/opencode/tools/
cp -r ~/.doom.d/modules/neo-emacs/typing-agent/opencode/skills/typing-agent \
      ~/.config/opencode/skills/
#+end_src

OpenCode 里就多了一个 =typing-agent= 工具和一个同名 skill。重启 OpenCode 生效。

** 查看文件也打开（follow 插件）

修改文件时 Emacs 会打开文件；"只是看看"的时候也应该打开。OpenCode 的 read
工具本身不碰 Emacs，所以模块带一个零依赖插件
=opencode/plugins/typing-agent-follow/=：它在 setup 里注册
=ctx.tool.hook("execute.before")=，凡是 =read= 一个真实文件，就先调用
=POST /open=，Emacs 像人一样弹出 buffer/文件选择框，输入文件名后跳过去，
并跳到 read 的 offset 行。

OpenCode 2.x 的插件是*目录*形式，且要在 =opencode.json= 的 =plugins= 数组里
登记（相对/绝对路径都行，必须是目录）：

#+begin_src bash
mkdir -p ~/.config/opencode/plugins
cp -r ~/.doom.d/modules/neo-emacs/typing-agent/opencode/plugins/typing-agent-follow \
      ~/.config/opencode/plugins/
#+end_src

#+begin_src json
"plugins": ["/Users/van/.config/opencode/plugins/typing-agent-follow"]
#+end_src

OpenCode 会监听配置目录并自动重载；改完刷新一下 OpenChamber 即可，不必重启。
用 =opencode plugin list= 应能看到 =typing-agent-follow=。行为：

- 只处理 =read=，=bash=、=grep=、=glob= 不触发；
- 同一个文件 1.2 秒内只打开一次，连续读不会反复抢焦点；
- Emacs 或服务没启动时静默跳过，绝不影响读文件；
- =TYPING_AGENT_FOLLOW=0= 可临时关掉，=TYPING_AGENT_URL=、
  =TYPING_AGENT_TOKEN=、=TYPING_AGENT_TOKEN_FILE= 可覆盖默认连接参数。

** MCP（可选，一般不需要）

OpenCode 端推荐直接用上面的原生 tool：它已经是最短路径，不需要 MCP，
也少一层进程和协议转换。

只有在这些情况才需要 MCP：

- 给 OpenCode 以外的 MCP 客户端用（Claude Desktop、Cursor、其他 agent）；
- 想把工具统一收进 MCP 管理。

模块自带一个零依赖的 MCP stdio server：=mcp/typing-agent-mcp.ts=，它只是把
Emacs 的 HTTP API 包装成 MCP 工具（=status=、=task=、=task_status=、=control=、
=save=、=open=、=goto=、=search=、=diff=、=recording=）。

OpenCode 的 =opencode.json= 里加（2.2.x 实测直接用 =mcp= 下放名字即可）：

#+begin_src json
"mcp": {
  "typing-agent": {
    "type": "local",
    "command": [
      "/Users/van/.bun/bin/bun",
      "/Users/van/.doom.d/modules/neo-emacs/typing-agent/mcp/typing-agent-mcp.ts"
    ],
    "enabled": true
  }
}
#+end_src

Claude Desktop 一类客户端：

#+begin_src json
{
  "mcpServers": {
    "typing-agent": {
      "command": "/Users/van/.bun/bin/bun",
      "args": ["/Users/van/.doom.d/modules/neo-emacs/typing-agent/mcp/typing-agent-mcp.ts"],
      "env": { "TYPING_AGENT_URL": "http://127.0.0.1:8765" }
    }
  }
}
#+end_src

验证：

#+begin_src bash
opencode mcp list          # 看到 typing-agent 且已连接
# 或者手动握手
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}' \
  | /Users/van/.bun/bin/bun ~/.doom.d/modules/neo-emacs/typing-agent/mcp/typing-agent-mcp.ts
#+end_src

注意：同时启用原生 tool 和 MCP 会出现两套同名能力，建议二选一。OpenCode 里用
原生 tool 即可；其他客户端用 MCP。

*** OpenChamber / 项目级配置（重要）

OpenCode 2.2.x 的 MCP 清单是*按项目目录*解析的：写在
=~/.config/opencode/opencode.json= 里的 =mcp= 只在 home 这个“项目”里生效。
在别的 git 仓库里运行 =opencode mcp list= 会显示 =No MCP servers configured=，
OpenChamber 的 MCP 面板（按当前项目查询）也就看不到。

解决办法是在项目根放一份 =opencode.json=，内容最简：

#+begin_src json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "typing-agent": {
      "enabled": true,
      "type": "local",
      "command": [
        "/Users/van/.bun/bin/bun",
        "/Users/van/.doom.d/modules/neo-emacs/typing-agent/mcp/typing-agent-mcp.ts"
      ]
    }
  }
}
#+end_src

放好后不需要重启 OpenCode，=opencode mcp list= 立刻会显示
=✓ typing-agent connected=；OpenChamber 刷新页面或重开 MCP 设置即可看到。

=~/.global_ignore= 已忽略 =opencode.json=，这份文件不会进 git。


* 启动服务与 token

服务默认监听 =127.0.0.1:8765=，启动时自动生成 token：

- 状态目录：=~/.local/state/typing-agent/=
- token 文件：=~/.local/state/typing-agent/token=（权限 600）
- 任务日志：=~/.local/state/typing-agent/tasks.jsonl=

=typing-agent-auto-start= 默认开启，Doom 启动后服务就在跑。手动控制：

#+begin_src bash
emacsclient -e '(typing-agent-server-start)'
emacsclient -e '(typing-agent-server-stop)'
emacsclient -e '(typing-agent-server-status)'
#+end_src

读 token：

#+begin_src bash
cat ~/.local/state/typing-agent/token
#+end_src

* 打字节奏

- 基础速度 6.5 字符/秒（=typing-agent-typing-speed=），约合每分钟 390 个字符
  （约 78 WPM），属于人类里打字偏快的那一档；每个字符还有 ±30% 的随机浮动。
- 小概率进入 burst（=typing-agent-burst-speed= 9.5 字符/秒），只是手顺了一小段，
  不会出现 20+ 字符/秒的机器连发。
- 标点、换行、开新行后都会停顿；极少数情况下会停下来「思考」一下。
- *不模拟打错字*：写进 buffer 的每个字符都是对的，没有打错再退格的表演。

* 窗口行为

任务开始时（以及 =/open=、撤销任务时）Typing Agent 会先把画面准备好，再开始敲键：

1. *查看或编辑别的文件先弹选择框*：=read=（follow 插件触发 =/open=）和编辑
   任务开始时，如果目标文件还没显示在眼前，不直接切 buffer，而是像人一样弹出
   选择框 —— 已经打开的 buffer 用 =consult-buffer=，否则按最近文件 / 项目文件 /
   =find-file= 选择 —— 停 =typing-agent-visit-pause=（默认 0.6 秒），再逐字符
   输入文件名（=typing-agent-visit-char-delay=，默认 0.15 秒一个字符），停
   =typing-agent-confirm-pause=（默认 1 秒）再回车跳过去。每一步都等上一步真的
   生效；超过 =typing-agent-visit-timeout=（默认 6 秒）才收掉选择框直接切换，
   不会卡在 minibuffer 里。文件已经在当前窗口时只跳行，不打扰画面。
2. 让窗口独占当前 frame（=delete-other-windows=），代码更大、录制更清楚；
3. 光标居中，方便观看。

选择方式由 =typing-agent-visit-method= 控制（=auto=、=consult-buffer=、
=consult-recent-file=、=project-find-file=、=find-file=、=direct=）；=direct= 退回
直接切换。默认 =auto=。窗口是否独占由 =typing-agent-maximize-window= 控制，默认开启。

任务开始时如果目标文件已经在窗口里，不会多弹一次选择框。任务结束*不做任何恢复*：
不会切回任务开始前的 buffer，也不会恢复原来的多窗口布局，画面就停在最后编辑或
查看的那个 buffer 上。失败、取消同样如此。

编辑的 buffer 里语法检查的诊断会改走回显区（=flycheck-display-errors-function=），
不再用 =flycheck-popup-tip=。原因很实在：=popup.el= 为了撑出提示框高度会往
buffer 末尾插空行，任务结束时那些空行会留在文件里。回显区不碰 buffer 内容，
诊断照样看得到；这个 buffer 局部设置会一直保留。
手动 =SPC t y r= 进入的录制模式仍会保存并在 =SPC t y R= 时恢复布局（那是用户显式操作）。

* HTTP API

所有请求都要带 =Authorization: Bearer <token>=。请求体与响应体都是 JSON。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | =/status= | 版本、服务、当前 buffer、活动任务、任务数 |
| GET | =/buffer= | 用户当前可见 buffer 的状态 |
| GET | =/tasks= | 最近 50 个任务 |
| GET | =/task/:id= | 单个任务详情（含最近日志） |
| POST | =/open= | 打开文件 ={file, line?}= |
| POST | =/goto= | 跳转 ={line}= 或 ={position, count?}= |
| POST | =/search= | 搜索 ={text, occurrence?, unique?}= |
| POST | =/task= | 提交编辑任务，立即返回 =202= 与任务 ID |
| POST | =/pause= | 暂停 ={id?}= |
| POST | =/resume= | 继续 ={id?}= |
| POST | =/stop= | 取消 ={id?}= |
| POST | =/undo= | 撤销任务并把快照写回文件 ={id?}= |
| POST | =/save= | 保存用户当前可见 buffer |
| POST | =/diff= | Unified Diff → =specs=，不执行 ={diff, base_dir?}= |
| POST | =/recording= | 录制模式 ={action: "start"/"stop", file?, line?, keep_window?}= |

不传 =id= 时，控制类接口作用于当前（或最近一个）任务。

** curl 示例

#+begin_src bash
TOKEN=$(cat ~/.local/state/typing-agent/token)
BASE=http://127.0.0.1:8765
AUTH="Authorization: Bearer $TOKEN"

curl -s -H "$AUTH" $BASE/status | jq .
curl -s -H "$AUTH" $BASE/buffer | jq '{buffer, line, evil_state}'
#+end_src

提交任务：

#+begin_src bash
cat > /tmp/task.json <<'JSON'
{
  "file": "/Users/van/project/src/main/java/UserService.java",
  "options": {"speed": 1.0},
  "operations": [
    {"type": "search_text", "text": "public User find(Long id) {"},
    {"type": "replace_region",
     "search": "        return repository.findById(id);\n",
     "replace": "        return repository.findById(id)\n                .orElseThrow(() -> new NotFoundException(id));\n"},
    {"type": "save_buffer"}
  ]
}
JSON

curl -s -X POST -H "$AUTH" -H 'Content-Type: application/json' \
     --data-binary @/tmp/task.json $BASE/task | jq .
#+end_src

然后轮询：

#+begin_src bash
curl -s -H "$AUTH" $BASE/task/<id> | jq '{status, index, total, error, result}'
#+end_src

状态值：=pending=、=running=、=paused=、=completed=、=failed=、=cancelled=。

=POST /task= 的请求体：

** 操作类型

每条操作必须有 =type=。

| type | 字段 | 需要状态 | 说明 |
|------|------|----------|------|
| =open_file= | =path= | 任意 | 只允许任务顶层 =file= |
| =goto_line= | =line= | Normal | 跳到行首 |
| =search_text= | =text=, =occurrence?=, =unique?= | Normal | 唯一定位 |
| =move_cursor= | =position=, =count?= | Normal | 见下 |
| =enter_insert= | =command?= | Normal | 默认 =i= |
| =type_text= | =text= | Insert | 逐字符输入，换行按行切换 Insert/Normal |
| =backspace= | =count?= | Insert | 退格 |
| =delete_text= | =text?= / =lines?= / =count?= | Normal | 删除定位文本、整行或光标后字符 |
| =delete_lines= | =count?= | Normal | =dd= |
| =insert_newline= | =count?= | Insert | 换行，行尾用 =ESC= + =o= |
| =indent= | =lines?= | Normal | 缩进 |
| =exit_insert= | — | Insert | 回 Normal |
| =replace_region= | =search=, =replace=, =occurrence?=, =unique?= | Normal | 整行先 =dd= 再用 =O=/=o= 逐行写回，行内用 Visual 删除 + =i= |
| =save_buffer= | — | 任意 | 校验并写盘 |
| =undo= | =count?= | 任意 | 撤销 |
| =pause= / =wait= | =ms?= | 任意 | 任务内停顿（默认 800ms） |

=move_cursor= 可用值：=line_start=、=line_end=、=next_line=、=prev_line=、
=buffer_start=、=buffer_end=、=word_forward=、=word_backward=、=char_forward=、
=char_backward=。

** 编辑行为（像人操作 Evil）

编辑器里看到的动作是真人会做的那些，而不是一次性灌入文本：

1. *新建文件走 dired*：目标文件不存在时，任务先像人一样在目录里创建它，而不是
   直接跳进一个空 buffer ——
   - 打开父目录的 dired（整个 frame 只剩它），停 =typing-agent-create-pause=
     （默认 0.5 秒）让目录列表出来；
   - 按 dired 的「新建空文件」键（Doom / Dirvish 下是 =c=，没有绑定就用 M-x），
     弹出 =Create empty file:=；
   - 逐字符输入文件名（=typing-agent-create-char-delay=，默认 0.12 秒一个字符），
     每敲一个字符都确认它真的出现在提示框里；
   - 停 =typing-agent-confirm-pause=（默认 1 秒）再回车创建；
   - 等文件真的存在、dired 刷新，在目录里定位到新文件，停一下再回车打开；
   - 进入文件 buffer 后才开始 Insert 输入。

   窗口在整个过程中停在 dired 里，录制里能看清文件名是怎么敲出来、文件是怎么出现在
   目录里的。每一步都等上一步真的生效才继续；任一步超过
   =typing-agent-create-timeout=（默认 6 秒）才放弃，记一条 =warn= 后退回直接创建，
   任务不会卡住。任务日志依次是：打开 dired 目录、按新建键、输入文件名、
   回车创建、回车打开、文件已创建。
   批处理环境（没有命令循环）仍然直接创建。
2. *按行切换模式*：多行 =type_text= 每写完一行就 =ESC= 回 Normal，再用 =o=
   开新行、重新进 Insert。行与行之间会明显停顿：=ESC= 与 =o= 之间是
   =typing-agent-line-break-pause=，新行出现到开始输入是
   =typing-agent-next-line-pause=。行中换行（行内替换跨行时）才用 =RET=。
3. *删除走操作符*：整行替换、=delete_lines=、=delete_text= 的整行情形都用 =dd=；
   删完再进 Insert 写新内容。行内文本用 Visual 删除 + =i=。
4. *缩进交给主模式*：行首缩进用 =TAB=（=indent-for-tab-command=）让主模式决定，
   再用空格/退格把列号校正到目标位置；如果主模式给出的 tab/空格写法与预期不同，
   最后按预期字符改写，保证落盘内容和任务描述逐字符一致。
5. *逐字符校验*：每段输入结束都会比对实际写入的内容，发现自动配对、自动缩进、
   snippet 展开等干扰就立刻失败，不会带着错误内容保存。

** 代码补全弹框（Eglot + corfu）

在 Eglot 管理的 =prog-mode= buffer 里，任务会像人一样一边输入一边看补全弹框，
而不是键完整个单词。开关是任务选项 =completion=（默认开）。

触发时机：

- 输入点号 =.= 或标识符字符（字母、数字、=_=、=$=）之后；
- 只有目标行后面还有标识符字符时才检查 —— 单词已经写完、行尾、标点时直接跳过，
  不会为了一次没有意义的补全白等 LSP；
- 字符串和注释里不触发。

行为：

1. 触发后等待 corfu 弹框出现（=typing-agent-completion-settle=，默认 0.16 秒），
   弹框出现后再停 =typing-agent-completion-popup-pause=（默认 0.12 秒），
   让弹框在屏幕上看得见。弹框没出现就按 =typing-agent-completion-retry-delay=
   重试，最多 =typing-agent-completion-max-retries= 次，然后继续正常输入。
2. *候选多个*：继续逐字符输入，让弹框自己筛；弹框保留在屏幕上，日志记
   「补全：N 个候选，继续输入」。
3. *只剩一个候选*：只有同时满足下面条件才选中，否则继续手动输入并记
   「候选与目标不匹配」：
   - 候选带 Eglot 的 =eglot--lsp-item=；
   - 候选的纯文本（LSP =insertText=，没有时用标签本身）正好是目标行从补全起点
     开始的前缀；
   - 它比已经输入的部分更长。

   选中后按实际写入的字符数推进字符索引，*绝不把已经补全的字符再敲一遍*。
   选中前会清掉 LSP item 里的 =textEdit=、=insertTextFormat=、
   =additionalTextEdits=、=command=、=data=，所以不会触发 snippet 占位符、
   自动 import 或 completion resolve 改写内容；插入仍然走 =corfu-insert=，
   undo 分组和弹框收尾与用户自己按 =RET= 一致。
4. 插入后立即校验 buffer 里那段文本正好等于候选纯文本，不一致就恢复已输入前缀
   并让任务失败（=typing-agent-verify-error=），绝不带着错误内容保存。
5. 退出 Insert（=ESC=）前先收起弹框，避免 ESC 被 corfu 的按键映射吃掉。

实现约定：

- 任务期间 =corfu-mode= 保持开启（原本没开就临时打开，结束后还原），但 buffer
  局部的 =corfu-auto= 置 nil，弹框只由补全状态机在需要时主动触发，避免自动弹框
  的时机和逐字符输入打架；
- 只处理 Eglot 的 capf；其他来源的候选不接管；
- 没有 Eglot 的 buffer 完全回到原来的逐字符输入，行为与以前一致。

** options

| 选项 | 默认 | 说明 |
|------|------|------|
| =speed= | 1.0 | 打字速度倍率（Characters per second 的乘数） |
| =allow_dirty= | false | 允许目标 buffer 有未保存修改 |
| =save= | false | 任务结束后自动保存 |
| =recording= | false | 进入录制模式整理窗口 |
| =completion= | true | 在 Eglot 管理的 buffer 里接入补全弹框（见上节） |
| =post_delay= | 1.5 | 结束前停顿秒数 |

** expected（可选，保存前校验）

| 字段 | 类型 | 说明 |
|------|------|------|
| =contains= | 字符串数组 | buffer 必须包含的片段 |
| =not_contains= | 字符串数组 | buffer 不能包含的片段 |
| =regexp= | 字符串 | 必须匹配的正则 |
| =content= | 字符串 | 完整内容必须一致 |
| =sha256= | 字符串 | 完整内容哈希必须一致 |
| =line_count= | 整数 | 行数必须一致 |

校验不通过时任务失败，且不会保存。

* 录制流程建议

1. =SPC t y r= 进入录制准备，摆好窗口。
2. 用 OpenCode 提交任务；默认 =speed= 1.0 已经是偏快的真人手速（约 6.5 字符/秒），
   想再慢一点设 0.6–0.8，一般不建议超过 1.2。
3. 中途想停下讲解就 =SPC t y p=，讲完 =SPC t y c=。
4. 出错或想重来，=SPC t y u= 回到任务开始前（文件一起回滚）。
5. 录完 =SPC t y R= 退出录制。

** 用 OpenCode 工具

安装上面那一步之后，直接让 agent 使用 =typing-agent= 工具即可，典型调用：

- =action="status"= 先探活；
- =action="task"= 传 =file= 与 =operations=，默认等待完成并返回 =status=/=result=/最近日志；
- =action="control"=、=control="pause"/"resume"/"stop"/"undo"= 控制任务；
- =action="diff"= 先把 patch 转成 =specs= 再提交。

* 第一版限制

- 单文件任务：=open_file= 只能打开任务顶层 =file=。
- 同一时刻只能有一个任务；重复提交返回 =409=。
- 目标文件不存在时会先在 dired 中创建；buffer 不能只读，默认不能有未保存修改。
- Diff 转操作是基础版：整段替换，不生成逐行最小编辑。
- 不做 OBS 自动控制、多 Agent、CGEvent 注入。
- 补全只接 Eglot + corfu，且只用候选的纯文本 =insertText=：不展开 snippet、
  不执行自动 import；没有 Eglot 的 buffer 逐字符输入不变。
- 任务期间请勿手动编辑目标 buffer，也不要用其他工具改同一个文件。

* 故障排查

- *连不上服务*：=emacsclient -e '(typing-agent-server-status)'=；端口被占用时改
  =typing-agent-server-port=。
- *401*：token 不匹配，重新读 =~/.local/state/typing-agent/token=。
- *409 有未保存修改*：先 =POST /save=，或确认后传 =options.allow_dirty: true=。
- *422 定位失败*：=search= 文本与文件实际内容不一致（缩进、换行、全角空格）。重新读文件再改。
- *打字太快/太慢*：调 =options.speed=，默认 1.0 为偏快的真人手速。
- *撤销失败*：buffer 撤销被禁用，或回退 =typing-agent-undo-max-steps= 步后仍未回到快照；
  错误会明确抛出，不会假装成功。
